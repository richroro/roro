# 잘나가는 쇼츠 재조사 프로토콜

"잘나가는 쇼츠 분석해서 업그레이드해줘", "요즘 뭐가 먹히는지 조사해줘" 같은 요청, 또는 플레이북이 3개월 이상
오래됐을 때 이 절차로 `references/playbook.md` 를 갱신한다. 한 번에 다 하지 말고 **조사 → 검증 → 반영** 순서를 지킨다.
(2026-09 최초 플레이북도 이 절차로 만들었다: 8개 렌즈 병렬 조사 → 핵심 주장 선별 → 렌즈 2개로 반박 시도 → 종합.)

## 1. 데이터 먼저

```bash
python .claude/skills/auto-shorts/scripts/research_trends.py     # 급상승 검색어·위키 인기 문서·Reddit·(키 있으면) 잘나가는 쇼츠
python .claude/skills/auto-shorts/scripts/report.py              # 우리 편들의 성과: 어떤 특징이 잘 됐나
```

`trends/latest.md` 의 유튜브 제목 패턴(물음표·숫자 비율, 길이 중앙값)과 `report.py` 의 제안이 **우리 데이터**다.
웹 글보다 이게 우선한다.

## 2. 웹 조사 렌즈 (병렬로, 각각 6회 이상 검색, 2025년 이후 자료 우선)

| 렌즈 | 찾는 것 | 검색어 예 |
|---|---|---|
| 훅 | 첫 1~3초 공식, 3초 유지율·스와이프율 수치, 화면 문구 vs 음성 | `shorts hook retention data`, `쇼츠 첫 3초 훅` |
| 한국 시장 | 잡학·썰·랭킹 등 포맷별 성과, 자막·보이스 스타일, 성공 채널 | `쇼츠 조회수 잘 나오는 형식`, `AI 나레이션 쇼츠 채널` |
| 페이스리스/AI | 성장·정체 니치, 유튜브 반복성·비진정성 정책, AI 표시 | `faceless channel 2026`, `YouTube inauthentic content policy` |
| 자막·비주얼·사운드 | 하이라이트 자막 효과, 안전영역 픽셀, 컷 빈도, BGM 레벨 | `shorts safe zone pixels`, `word highlight captions retention` |
| 플랫폼 규칙 | 길이 vs 배급, 지표 정의, 수익화 기준, Reels/TikTok 차이, 업로드 시간 | `Shorts viewed vs swiped away`, `릴스 알고리즘 2026` |
| Threads | 스레드 트렌드·알고리즘, 훅 테스트 활용, 영상 제한, API 유무 | `스레드 알고리즘`, `Threads API trending` |
| 데이터 소스 | 무료 엔드포인트 현황(구글 트렌드 RSS, 위키 pageviews, Reddit JSON, YouTube API 할당량) | `google trends rss geo KR`, `youtube data api quota search.list` |
| 사례 | 조회수 높은 사실·상식 쇼츠의 첫 문장·구조·길이 | `조회수 1000만 쇼츠 상식`, `viral educational shorts breakdown` |

각 주장은 `주장 / 근거(수치) / 출처 URL / 날짜 / 신뢰도 / 우리 파이프라인에 어떻게 반영` 형태로 적는다.
마케팅 블로그의 숫자는 신뢰도 medium 이하. 플랫폼 공식 문서·측정 데이터만 high.

## 3. 검증 (기본값을 바꿀 주장만)

플레이북 규칙이나 SKILL.md 기본값을 바꾸게 될 12~16개 주장을 고르고, 각각에 대해
(a) **출처 렌즈**: 다른 출처로 뒷받침되는가, 반박 자료가 있는가, 숫자는 측정값인가 추정인가
(b) **적용 렌즈**: 한국어·TTS·정지 이미지·40~60초 쇼츠에도 해당되는가, 얼굴 노출/트렌드 음원 전제는 아닌가
로 반박을 시도한다. 둘 다 통과 → [확인됨], 하나 통과 → [부분확인], 둘 다 실패 → 규칙에서 빼고 9절에 기록.

## 4. 반영 규칙

- 플레이북 규칙 문장마다 출처 도메인과 검증 태그를 붙인다. 태그 없는 규칙은 넣지 않는다.
- SKILL.md 기본값(길이·씬 수·자막 크기·전환·BGM 볼륨 등)은 **[확인됨] + 우리 성과 데이터가 같은 방향** 일 때만 바꾼다.
  둘 중 하나만 있으면 플레이북에 "실험 중"으로 적고 다음 편에서 A/B 로 시험한다.
- 바꾼 것은 플레이북 맨 아래 `업데이트 기록` 에 날짜·근거 수·바꾼 항목을 남긴다.
- 반박된 통념은 지우지 말고 9절에 남긴다 — 다음 조사에서 되살아나는 걸 막는다.
