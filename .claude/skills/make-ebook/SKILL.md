# 전자책 제작 (본문 + 판매 랜딩페이지)

주제 하나를 받아서 **실전형 전자책 본문(Markdown)** 을 쓰고, 사용자가 "판매"를
언급하면 **판매용 랜딩페이지(HTML)** 를 Artifact로 발행한다. 화려한 이론서가
아니라 독자가 바로 써먹을 수 있는 실용서를 지향한다.

## 언제 이 스킬을 쓰는가
- "○○ 관련 전자책 만들어줘" — 주제 기반 전자책 신규 제작
- "이거 전자책으로 팔 수 있게 해줘" — 본문 + 랜딩페이지 둘 다
- 이미 전자책을 만든 뒤 "판매하도록", "랜딩페이지도 만들어줘" — 랜딩페이지만 추가
- "전자책 챕터 더 늘려줘/다듬어줘" — 기존 본문 보강 (이 스킬의 구조를 그대로 따름)

## 0단계. 범위 확정 (생략하지 말 것)

주제만 던져진 경우, 곧바로 쓰지 말고 **AskUserQuestion으로 3가지를 먼저 확인**한다.
사용자가 이미 답을 준 항목은 다시 묻지 않는다.

1. **타겟 독자** — 누가 이 책을 읽는가 (예: 직장인 / 1인 사업가·프리랜서 / 개발자 / 입문자 전반)
2. **핵심 주제·도구** — 무엇을 다루는가 (주제에 맞게 선택지를 직접 구성. 예: AI 활용 / 노코드 툴 / 특정 소프트웨어 / 종합)
3. **분량·형식** — 짧은 실용서(10~15쪽) / 표준 분량(20~30쪽) / HTML 아티팩트로도 제작할지

답변에 따라 톤·챕터 수·예시 밀도를 조정한다. 답이 없거나 애매하면 "1인
사업가·프리랜서 + 실전 위주"를 기본값으로 삼는다 — 가장 넓은 독자층이면서
바로 적용 가능한 조언을 원하는 경우가 많다.

## 1단계. 파일 위치

프로젝트 루트에 `<주제-slug>-ebook/` 폴더를 만들고 그 안에 저장한다.
(이번 세션 예시: `automation-ebook/`)

```
<slug>-ebook/
  <책제목>.md      # 전자책 본문 (필수)
  landing.html      # 판매 랜딩페이지 (판매 언급 시에만)
```

## 2단계. 본문 작성 (Markdown)

Write 도구로 직접 파일을 쓴다. 아래 구조를 뼈대로 삼되, 주제에 맞게 챕터
내용은 새로 구성한다 — 템플릿을 그대로 복사하지 말 것.

1. **표지/후킹 인트로** — 책 제목 + 부제, "이 책을 읽어야 하는 이유" 1문단,
   불릿 3~5개로 "이 책에서 얻게 될 것" 명시
2. **목차** — 챕터 번호 + 제목 나열
3. **본문 챕터 (보통 7~9개)**
   - 문제 진단/동기부여 챕터로 시작 (숫자·표로 문제의 크기를 보여줄 것)
   - 이후 챕터는 실행 가능한 영역별로 쪼갠다 — 설명은 짧게, **표/체크리스트/
     복붙 가능한 템플릿·프롬프트**를 반드시 포함
   - 마지막 본문 챕터는 실행 로드맵(주차별/단계별 체크리스트)으로 마무리
4. **부록** — 주제에 맞는 재사용 자산 모음 (프롬프트 라이브러리, 템플릿 목록,
   체크리스트 등 — 번호 매겨 나열)
5. **맺음말** — 3~5문장, 행동 촉구로 마무리

**품질 기준**
- 모든 표/프롬프트/템플릿은 실제로 복붙해서 쓸 수 있는 완성형이어야 한다
  (플레이스홀더는 `[이렇게]` 형태로 명확히 표시)
- 과장된 숫자·검증되지 않은 통계를 지어내지 않는다. 예시 수치는 "일반적으로",
  "평균적으로" 같은 표현으로 예시임을 분명히 한다
- 법률·세무·의료 등 전문 자격이 필요한 영역은 "전문가 확인 필요"를 명시한다
- 분량은 0단계에서 정한 기준을 따른다 (짧은 실용서면 챕터 수를 5~6개로 줄임)

## 3단계. 판매 랜딩페이지 (사용자가 "판매"를 언급했을 때만)

랜딩페이지는 편집적(editorial) 처리가 필요한 결과물이다. **작성 전에 반드시
`artifact-design` 스킬을 먼저 로드**하고 그 지침(팔레트/타이포/레이아웃을
주제에 맞게 직접 설계, AI스러운 클리셰 배색 회피, 라이트/다크 테마 대응)을
따른다.

### 랜딩페이지 구조 (권장 섹션 순서)
1. 히어로 — 이북 제목/부제 + 핵심 약속 + CTA 버튼 + 신뢰 지표(과장 없이)
2. 문제 진단 — 본문 1~2장 내용을 시각화 (막대 차트 등, 실제 책 내용 기반 수치만 사용)
3. 목차 미리보기 — 챕터를 번호 리스트로 (실제 순서와 일치해야 함)
4. 샘플 미리보기 — 책에 실제로 있는 프롬프트/템플릿 1개를 카드로 노출 (복사 버튼 가능)
5. 대상 확인 — "이런 분께 맞음 / 안 맞음"
6. 구성/포함 내역
7. 가격 — 실제 결제 연동 없이 가격 카드 + CTA. **주의사항 문구를 반드시 넣는다**:
   "결제는 실제 판매 채널(크몽·탈잉·Gumroad 등) 연동이 필요합니다"
8. FAQ (접이식 `<details>`)
9. 푸터

### 절대 하지 말아야 할 것
- **가짜 후기/구매자 수를 지어내지 않는다.** ("1,000명이 구매했어요" 같은
  검증 불가능한 사회적 증거 금지). 후기 섹션이 필요하면 사용자에게 실제 후기가
  있는지 먼저 묻는다.
- **실제 결제 정보를 받는 척하는 폼을 만들지 않는다.** 카드번호 입력창 등은
  절대 넣지 않는다 — CTA는 "구매하기" 버튼 정도로만 두고, 실제 결제는 사용자가
  붙일 채널(크몽/탈잉/Gumroad/스마트스토어 등)에 위임한다.
- 가격은 예시 수치로 넣되, 사용자에게 "예시 가격이니 원하는 금액으로
  바꾸라"고 안내한다.

### 발행
```
Artifact({ file_path: "<slug>-ebook/landing.html", favicon: "<주제와 어울리는 이모지 1~2개>" })
```
`<title>` 태그로 아티팩트 제목을 지정한다 (title 파라미터는 태그가 없을 때만
적용됨).

## 4단계. 마무리 안내

사용자에게 다음을 명확히 전달한다.
- 본문 파일 경로
- (해당 시) 랜딩페이지 Artifact URL
- 랜딩페이지의 "구매" CTA는 실제 결제 연동이 필요하다는 점
- 가격은 예시이므로 조정 가능하다는 점
- 추가로 가능한 다음 작업 제안 (PDF/EPUB 변환, 표지 이미지, 챕터 확장 등) —
  단, 먼저 만들지 말고 필요 여부만 짧게 제안
