# 카페24 앱스토어 서비스 분석 및 선정 (2026-09)

## 1. 한 줄 결론

**"AI 답변 도우미"** — 상품문의·후기·1:1 게시판의 미답변 글을 모아, 매장 정책과 상품·주문 정보를 근거로 답변 초안을 만들고 운영자 승인 후 게시하는 앱을 만든다.
이유는 세 가지다. (1) 카페24 스스로 "급증하는 고객 문의가 소규모 쇼핑몰·1인 셀러의 가장 큰 진입 장벽"이라고 말할 만큼 수요가 검증돼 있고, (2) 플랫폼의 자체 해법(카페24 PRO)과 대형 앱(채널톡)은 유료 상위 티어에 묶여 있어 롱테일 셀러용 저가 대안이 비어 있으며, (3) 게시판·상품·주문 Admin API가 모두 열려 있어 1인 개발로 MVP를 완주할 수 있다.

## 3. 플랫폼 구조 (개발 관점)

- **앱 유형**: Admin API 기반 관리자 앱(OAuth 2.0), 프론트 스크립트 앱(ScriptTags), 둘의 조합.
- **인증**: `https://{mall_id}.cafe24api.com/api/v2/oauth/authorize` → code → `/oauth/token` (Basic 인증). 액세스 토큰 2시간, 리프레시 토큰 2주.
- **앱 실행 검증**: 관리자가 앱을 열면 `mall_id, shop_no, user_id, user_name, user_type, timestamp, lang, nation, is_multi_shop, hmac` 파라미터가 오고, `hmac`을 제외한 쿼리스트링을 client_secret으로 HMAC-SHA256 → base64 한 값과 비교한다(타임스탬프 ±2시간).
- **웹훅**: 이벤트 번호 기반. 게시글 등록 90033, 댓글 등록 90034, 앱 삭제 90077, 앱 결제 90157 등.
- **과금**: `POST /admin/appstore/orders` 로 결제 주문을 만들면 `confirmation_url`이 돌아오고, 결제 결과는 `/admin/appstore/payments` 와 웹훅으로 확인한다.
- **심사/정산**: 개발자센터에 앱 등록 → 심사 → 스토어 게시. 개인 판매자는 월 정산 한도(매출 200만 원)가 있으므로 사업자 등록이 사실상 필요하다.

## 7. 선정 서비스 정의: AI 답변 도우미

### 7.1 문제
상품문의·후기·1:1 게시판은 카페24 몰의 기본 CS 채널이지만, 1인 셀러는 매일 같은 질문("배송 언제 오나요", "사이즈 어떤 게 맞나요", "교환 되나요")에 손으로 답하느라 시간을 쓴다. 채널톡·카페24 PRO는 해결책이지만 월 수십만 원대의 상위 티어다.

### 7.2 핵심 기능 (MVP, 이 저장소에 구현)
1. **설치·인증**: 앱 실행 HMAC 검증 → OAuth 동의 → 토큰 저장·자동 갱신.
2. **게시판 연결**: 카페24 게시판 목록을 불러와 답변할 게시판과 방식(답변글/댓글)을 선택.
3. **정책 지식**: 배송·교환/환불·운영시간·FAQ를 입력하면 AI가 이 범위 안에서만 답한다.
4. **근거 수집**: 글에 연결된 상품 정보(설명·옵션·품절 여부)와, 회원 문의면 **작성자 본인의 최근 90일 주문·배송 상태(송장 포함)** 를 조회해 답변에 반영. 주소·연락처·결제수단은 AI에 전달하지 않는다.
5. **초안 생성**: Claude 구조화 출력으로 `카테고리 / 확신도 / 사람 확인 필요 여부 / 답변 / 내부 메모 / 사용한 근거`를 받는다.
6. **승인 게시**: 운영자가 수정 후 버튼 한 번으로 답변글(`reply_article_no`) 또는 댓글로 게시.
7. **자동 게시(프로)**: 확신도·카테고리 조건을 만족하고 "사람 확인 불필요"인 초안만 자동 게시.
8. **실시간 + 폴링**: 게시글 등록 웹훅(90033)으로 즉시 처리, 폴링은 누락 안전망.
9. **과금**: 카페24 과금 API로 요금제 결제, 결제 내역 확인 후 활성화.

### 7.3 차별점
- **주문 연동 답변**: "배송 언제 오나요"에 실제 송장번호·상태로 답한다. 채팅 도구가 아닌 게시판 원생 워크플로에 붙는다.
- **승인형 기본값**: 자동 게시는 옵션이며 기본은 사람이 검토한다 → 오답 리스크가 낮아 심사와 신뢰에 유리.
- **가격**: 좌석 과금이 아니라 건수 과금. 무료 티어로 진입 장벽을 없앤다.

### 7.4 요금제와 원가

가정: 초안 1건당 입력 약 2,500토큰(시스템 프롬프트 800토큰은 캐시 적중), 출력(사고 포함) 약 1,000토큰. Claude Opus 5 기준 입력 $5/MTok, 출력 $25/MTok, 환율 1,400원.

| 요금제 | 월 요금 | 월 초안 한도 | AI 원가(상한) | 매출총이익 |
|---|---|---|---|---|
| 무료 | 0원 | 30건 | 약 1,600원 | 획득 비용으로 간주 |
| 스타터 | 29,000원 | 300건 | 약 15,800원 | 약 45% |
| 프로 | 89,000원 | 1,000건 | 약 52,500원 | 약 41% |

- 카페24 스토어 수수료(판매대금 정산 시 선취)는 별도. 원가를 낮추려면 프로 티어를 Claude Sonnet 5($2/$10)로 돌리는 선택지가 있다(원가 약 60% 절감).
- 사용량 상한은 앱 내부에서 강제한다(`plans.js`).

### 7.5 로드맵
1. **MVP (이 저장소)**: 위 1~9.
2. **품질**: 매장별 과거 답변 학습(운영자가 수정한 최종 답변을 few-shot으로 재사용), 답변 템플릿 라이브러리.
3. **채널 확장**: 카카오톡 채널 상담·네이버 톡톡 문의 수집(각 플랫폼 API 계약 필요).
4. **인사이트**: 문의 카테고리 통계 → "이 상품은 사이즈 문의가 많음 → 상세페이지 보완" 제안. 리뷰 감성 요약.
5. **B 모듈**: AI 검색(ChatGPT 쇼핑앱 등) 대응 상품 데이터 정비.

### 7.6 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 카페24 PRO의 CS 자동화가 비-PRO로 확대 | 게시판 원생 워크플로·주문 연동·건수 과금으로 세그먼트 차별화, 채널 확장(4)로 이탈 방어 |
| AI 오답이 고객에게 노출 | 기본 승인형, 정책 밖 질문은 `needs_human`, 자동 게시는 프로 + 확신도 조건 |
| 개인정보 | 주문 조회는 작성자 본인 회원 ID로만, 주소·연락처·결제수단 미전달, 토큰은 서버 DB에만 저장 |
| API 스펙 변동 | 버전 헤더 고정 옵션, 클라이언트 계층 분리, 목 서버로 회귀 테스트 |
| 심사 요건(개인정보 처리방침, 권한 최소화) | 요청 권한을 5개로 최소화, 문서화(`docs/app-store-submission.md`) |
